## Каталог v2 (что нового в этой версии)

```
data/catalog/**.json ──► python tools/build_catalog.py ──► data/catalog.db + rust_backend/catalog.db
   (файл на модель,          (проверка схемы и ссылок,            │
    справочники)              формулы оценок камер)               ▼  rusqlite, один раз при старте
                                                         phonepicker-server (в памяти) ──► index.html
```

- `python tools/generate_random_catalog.py` — создаёт демо-каталог из `data/phones_seed.csv` (seed 2026, результат
  повторяется байт в байт). Когда пойдут настоящие данные, этот скрипт больше не запускают — файлы правят по ТЗ.
- `python tools/build_catalog.py` (`--check` — только проверка) — собирает SQLite. Только стандартная библиотека Python;
  если установлен `jsonschema`, файлы дополнительно сверяются со схемой. Кроме формы проверяется честность данных
  (правила H1–H11, R1 из раздела 0.1 ТЗ): случайные числа под пометкой `verified`, «проверено» без ссылок, угаданные
  сенсоры, дубли моделей, пересчитанные из рублей `msrp_usd`, даты-заглушки, справочники не по схеме.
- `python tools/build_catalog.py --check --final` — критерии готовности раздела 16 ТЗ для сдачи реальных данных
  (демо-набор их, естественно, не проходит).
- Сервер ищет каталог так: `CATALOG_PATH` → `catalog.db` рядом с exe → в текущей папке → копия, встроенная в бинарник.
- Связь с обученной моделью — по slug (`Samsung Galaxy S25+` → `samsung-galaxy-s25-plus`); строки старой базы вида
  «iPhone 17 Pro 512GB» стали конфигурацией модели `apple-iphone-17-pro`.
- Подбор с `"variants": true`: для каждой модели берётся самая дешёвая конфигурация с ОЗУ ≥ `min_ram` и ПЗУ ≥ `min_rom`,
  её цена идёт в бюджет и штрафы, одна строка на модель. Новые фильтры: `min_ram`, `min_optical_zoom`, `need_macro`,
  `hide_bad_quirks`, `special_only`, `special` (коды категорий). Без них подбор совпадает с прежним (golden-тест).

Новые маршруты:

| Метод | Путь | Что делает |
|---|---|---|
| `GET` | `/api/phone/{slug}` | Карточка модели: конфигурации с историей цен, камеры (железо / обработка / итог), «приколы», категории, фото |
| `GET` | `/api/special` | «Смартфоны с интересными возможностями» по категориям, включая модели вне подбора (TriFold, iPhone Duo, Robot Phone) |
| `GET` | `/placeholder/{slug}/{n}.svg` | Демо-заглушка фото, пока нет настоящего снимка |

`/api/meta` дополнительно отдаёт `version_name` и `catalog` (статистика, варианты ОЗУ, категории, типы «приколов»).

Проверка: `cargo test --release` — golden-тест (60 анкет как в Python) и `tests/catalog.rs` (связь с моделью, целостность,
фильтры ОЗУ / зума / макро / минусов / категорий, одна строка на модель). Сайт этой версии — `run.bat`, порт **8081**,
чтобы не мешать основной версии на 8080.

Python по-прежнему **обучает** модели: метки классов, веса признаков, KMeans по шпилям, нейросеть MLP и справедливую цену.
Rust **считает подбор** по анкете: полезность телефонов, жёсткие требования, прямой проход нейросети, мягкий бонус группы,
разнообразие выдачи, блоки и ценовые сегменты. Логика — построчный порт `src/ml/recommender.py` и `src/ml/labeling.py`.

```
Python (обучение, раз в N дней)            Rust (каждый запрос)
phones.db → PhonePipeline.fit()  ──► model.json ──► phonepicker-server ──► HTTP API ──► index.html
            PriceModel.fit()          (≈380 КБ)       (один файл ≈2 МБ)
```

## Запуск

```bash
# 1. Выгрузить обученную модель (из корня проекта)
python tools/export_for_rust.py --golden 60     # → rust_backend/model.json и golden.json

# 2. Собрать и запустить сервер
cd rust_backend
cargo build --release
./target/release/phonepicker-server              # Windows: target\release\phonepicker-server.exe
# открыть http://localhost:8080
```

Модель и страница встроены в бинарник при сборке, поэтому для запуска на другой машине нужен только
сам файл `phonepicker-server`. Python там не нужен. Новую модель без пересборки можно подложить так:
`MODEL_PATH=model.json ./phonepicker-server`. Порт меняется переменной `PORT`.

Страницу `static/index.html` можно открыть и отдельно, файлом или с другого хоста: она обратится к `http://localhost:8080`
либо к адресу из параметра `?api=http://сервер:8080`. CORS на сервере открыт.

## API

| Метод | Путь | Что делает |
|---|---|---|
| `POST` | `/api/recommend` | Анкета (JSON, поля как в `SURVEY_FIELDS` + `budget_min`, `top_n`) → класс, вероятности, топ-N, блоки, сегменты, `compute_us` |
| `GET` | `/api/meta` | Ползунки, пресеты, группы, метрики модели — для построения формы |
| `GET` | `/api/bench?n=5000` | Замер скорости на n случайных анкетах |
| `GET` | `/api/photos` | Фото по id модели: своя папка `photos/` + Wikimedia Commons |

Пример запроса:

```bash
curl -X POST localhost:8080/api/recommend -H 'content-type: application/json' \
     -d '{"budget_rub": 40000, "imp_camera": 9, "photo": 1, "need_nfc": 1, "min_rom": 256}'
```

Поля, которых нет в запросе, берутся по умолчанию, как в анкете приложения.

Отличия сайта от Python-версии (вся логика оценки при этом та же, см. тест ниже):

- `strict_range: 1` — страница шлёт бюджет как строгий потолок; в Python-версии допускалось превышение до +10%.
- В выдаче только телефоны, которые проходят все условия. Python добивает выдачу до 10 моделей ближайшими
  неподходящими; сайт вместо этого показывает подсказку и кнопки «Поднять бюджет до …» / «Любая система» и т. п.
- `split: true` включает разбиение на ценовые категории (Бюджетные / Средний бюджет / Флагманы); по умолчанию выключено.

## Проверка, что Rust считает так же, как Python

```bash
cargo test --release -- --nocapture     # совпало 60 анкет из 60
```

Тест берёт 60 случайных анкет из `golden.json` (их ответы посчитал Python) и сверяет вероятности классов
(до 1e-6), число подходящих моделей, лучшую группу, подсказку, топ-10, блоки выдачи и сегменты.

## Скорость

На одной и той же машине и одном ядре:

| | Один подбор |
|---|---|
| Python: sklearn + pandas, `recommend()` | ≈ 8,8 мс |
| Rust: `engine::recommend()` | ≈ 50–60 мкс |

Это примерно в 150 раз быстрее, или около 15 000 подборов в секунду на ядро. Замер запускается кнопкой на странице или запросом `/api/bench`.

## Фото телефонов

Ссылки на фото хранятся в базе — таблица `phone_photos` (`phone_id`, `url`, `author`, `license`, `source_page`,
`position`, `origin`). Встроенный набор лежит в `data/phone_photos_seed.csv` и загружается в базу при запуске,
как и сам каталог; свои ссылки можно добавить через `db.add_photo(phone_id, url, …)` или строкой в этот CSV
(колонка `model` — как в `phones_seed.csv`). `tools/export_for_rust.py` выгружает фото в `model.json`, сайт показывает их
на карточках вместе с автором и лицензией.

Сейчас в базе 99 фото у 41 модели из 286 — все из Wikimedia Commons под свободными лицензиями (CC0, CC BY, CC BY-SA).
Для остальных моделей открытых снимков с понятной лицензией нет: сайты вроде GSMArena закрывают доступ ботам,
а внутренние API маркетплейсов не предназначены для сторонних приложений. Кому не хватает фото — в `photos_todo.csv`.

Кроме базы, можно положить файл в папку `photos/` рядом с местом запуска (или `PHOTOS_DIR`): `<id>.jpg`, `<id>-2.jpg`, …
(jpg, png, webp, avif). Сервер подхватывает такие файлы без перезапуска и показывает их первыми.

## Файлы

- `src/model.rs` — загрузка `model.json`, прямой проход MLP, предрасчёт мягкой принадлежности группам.
- `src/engine.rs` — подбор: полезность, требования, оценка, разнообразие, блоки, сегменты, подсказки.
- `src/main.rs` — HTTP-сервер (axum).
- `static/index.html` — веб-интерфейс. Шрифты Unbounded и Onest (SIL OFL) лежат в `static/fonts` и тоже встроены в бинарник.
- `tests/golden.rs` — сверка с Python.
